Architectural Design & Software Design Principles

See architecture as the bridge from requirements to a system structure, then use design principles to keep that structure understandable, adaptable, and testable.

Learning focus

Understand what software architecture is, why it matters, where it fits in the methodology, and how architectural decisions connect to software design principles.

Core lecture

What you need to understand

  • Software architecture describes the high-level structure of a system: its major elements, interfaces and interactions, composition patterns, constraints, and design rationale.
  • Architectural design is a decision-making process. Different types of systems call for different design methods and architectural styles.
  • Architecture follows requirements work and guides later interaction, domain, behavior, class design, implementation, integration, and deployment.
  • The chapter combines two outcomes: select or create a suitable architecture, then apply design principles that improve understandability, changeability, reuse, testability, and maintenance.
