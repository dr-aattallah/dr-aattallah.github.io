CONCEPT 1

User stories and value

A user story captures a goal and benefit from a stakeholder perspective; it is a conversation starter, not a complete specification.

ROOMNOWAs a student, I want to see available rooms so I can choose a suitable study space.
CONCEPT 2

Acceptance criteria

Specify observable outcomes including normal, alternate and failure conditions. Acceptance criteria connect requirements to testing.

ROOMNOWGiven a room already reserved, when a conflicting request arrives, the system rejects it with a clear message.
CONCEPT 3

Use cases when useful

A concise use case describes actor goal, trigger, preconditions, main success path and important exceptions. Use it for interaction complexity rather than producing a diagram for every tiny feature.

ROOMNOWBook room: select room and time, check eligibility and availability, confirm booking; alternative: slot no longer available.
CONCEPT 4

Priority and change

Prioritize by user value, risk, dependency and feasibility. Document change impact on scope, model, implementation and tests.

ROOMNOWA waitlist request may be valuable but can be postponed if conflict prevention is not reliable.
CONCEPT 5

Traceability

Maintain simple links from requirement/story to issue, design decision and test; traceability is useful when it helps answer change-impact questions.

ROOMNOWFR-01 → issue #12 → booking validation → test conflict_booking_rejected.
