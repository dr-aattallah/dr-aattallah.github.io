CONCEPT 1

Purpose of models

A model simplifies selected aspects of a system to support a decision or conversation; a model is not valuable merely because it exists.

ROOMNOWA room-booking domain model helps decide which concepts and relationships must be represented.
Practice the engineering judgment

What failure could occur if this principle is ignored? Propose a better decision and describe how you would verify it.

CONCEPT 2

Domain concepts

Identify important concepts and associations before implementation classes; distinguish real-world concepts from UI widgets.

ROOMNOWRoom, Booking, User, TimeSlot and BookingPolicy; a Booking refers to a Room and requester.

What failure could occur if this principle is ignored? Propose a better decision and describe how you would verify it.

CONCEPT 3

Class model basics

Use classes, attributes, associations and multiplicity to communicate structure. Avoid excessive implementation detail at this stage.

ROOMNOWOne Room may have many Bookings; each Booking belongs to exactly one Room.

CONCEPT 4

Interaction models

Sequence diagrams show messages among participants for a scenario. Focus on responsibilities, important checks and ordering.

ROOMNOWUser requests booking → service checks policy → repository checks overlap → service returns result.

CONCEPT 5

Behavior and model consistency

Interpret activity/state models selectively when branching or lifecycle states are essential; check consistency with requirements.

ROOMNOWA Booking moves from Requested to Confirmed or Rejected, with cancellation only from permitted states.

APPLICATION · CLASS / PROJECT

Apply and transfer

Challenge 1: individually critique an ambiguous requirement and inconsistent domain/interaction model; improve it and justify how to validate the correction.

Evidence standard: an understandable decision, a specific artifact or link where appropriate, a verification method, and a brief justification. Studios are formative; Challenges are individual graded work when scheduled.

Self-check (ungraded)

  1. State two concepts and distinguish their purposes.
  2. Explain one RoomNow design or workflow trade-off.
  3. Identify a defect or unsupported claim in a sample artifact.
  4. Suggest a correction and evidence that could validate it.
  5. Transfer the idea to a different system.
