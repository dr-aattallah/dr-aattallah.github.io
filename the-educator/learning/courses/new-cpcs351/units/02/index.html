CONCEPT 01

Why process matters

A software process organizes specification, development, validation and evolution. The activities remain essential; their sequence, feedback cadence and documentation depend on the context.

ROOMNOW EXAMPLERoomNow begins as a small student prototype. When the university plans a campus-wide service, requirements, data access and reliability constraints change. A team must decide how to learn safely and deliver useful increments.

Explain this concept in your own words, identify one risk if it is ignored, and give a second example from a different software system.

CONCEPT 02

Predictive, iterative and incremental

Predictive planning is useful when requirements and approvals are relatively stable, and when formal handoffs are required. Iterative work revisits a solution using feedback; incremental delivery adds useful capabilities in slices. Iterative and incremental are related but not identical.

ROOMNOW EXAMPLEFor RoomNow, a team might deliver search first, then booking, then cancellation. Each increment is validated with users; the team may revisit its search design after feedback.

CONCEPT 03

Agile is disciplined feedback

Agile approaches prioritize collaboration, frequent feedback, adaptable planning and working software. They do not mean no documentation, no architecture or no quality controls. A short iteration has a goal, selected backlog items, implementation, review and adjustment.

ROOMNOW EXAMPLEA team discovers that bookings need a waitlist. It records the change, discusses priority and impact, and adjusts its next iteration instead of silently adding unreviewed work.

CONCEPT 04

Backlog, issue and acceptance criteria

A product backlog is an ordered set of work items. An issue describes one traceable unit of work: problem or feature, scope, owner, acceptance criteria and status. A task is done when evidence supports the acceptance criteria—not simply when someone moves a card.

ROOMNOW EXAMPLEWeak issue: 'Fix bookings.' Better issue: 'Prevent overlapping active bookings for the same room and time. Given an existing booking, when another user requests the same slot, the system rejects the conflict and explains why.'

CONCEPT 05

Roles and working agreement

Clarify who coordinates, implements, reviews and tests. Responsibilities can rotate. A working agreement covers communication, meeting cadence, issue ownership, review before merge, response expectations and conflict escalation.

ROOMNOW EXAMPLEAvoid treating a named role as proof of collaboration. Inspect whether decisions and changes are actually visible to the team.

CONCEPT 06

GitHub workspace: minimum viable setup

Create a shared repository with README; establish a project board with To do, In progress and Done; create three meaningful issues with acceptance criteria and owners. Use the browser interface in Studio 1. Detailed branching, pull requests and merging are taught later in Unit 07.

ROOMNOW EXAMPLERepository stores versioned artifacts; issue tracks a change; board visualizes workflow. A card moving to Done without verification is not engineering evidence.

GUIDED APPLICATION · FORMATIVE

Studio 1 — Team Workflow

In teams, create or join one repository, a simple board, a working agreement and three issues for RoomNow or your approved project. Each issue must state an observable completion condition. Assign owners, prioritize work, and explain why the first item should be done first.

EXPECTED EVIDENCEFormative: working links, understandable issues, realistic ownership, clear acceptance criteria, one justified priority decision.
