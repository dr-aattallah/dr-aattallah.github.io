GROUP PROJECT · 30 MARKS

Turn a real problem into an engineered solution.

Work as one team to define a meaningful problem, discover requirements, design the system, model its behavior and architecture, then show how the solution can be verified and validated.

PROJECT JOURNEY

Four connected phases

Each phase must build on the previous one. Do not treat the diagrams as separate assignments.

1

Project Definition

Establish the problem and project boundary.

  • Problem & objectives
  • Goals and scope
  • Included / excluded features
  • Team organization
2

Business Requirements

Translate the problem into stakeholder needs.

  • Stakeholders & actors
  • Functional + NFRs
  • Use Case Diagram
  • 2 detailed use cases
3

Design & Structuring

Transform requirements into an object-oriented structure.

  • Candidate classes
  • Class Diagram
  • Relationships & multiplicity
  • Object Diagram
4

Behavior & Architecture

Show collaboration, workflow and system organization.

  • Sequence Diagram
  • State Diagram
  • Activity Diagram
  • System Architecture
Problem → Scope → Requirements → Use Cases → Classes → Behavior → Architecture → Testing
FINAL INTEGRATION

Testing, traceability & presentation

Define testing objectives and strategy, provide representative requirements-based test cases, and check end-to-end traceability. The final presentation should communicate the complete project and the reasoning behind major engineering decisions.
