Topic 06 · Lesson 10

Design for the Future

A design is not successful only because it works today. Good design prepares for reuse, change, technology evolution, portability and testing.

10of 10 pages
Learning focus

Apply the remaining source design principles and synthesize Topic 06 into one architecture-and-design decision model.

Future-facing principles

Five ways to avoid designing yourself into a corner

♻️

Increase reusability

Generalize where practical, use good cohesion/coupling/abstraction, add extension hooks and keep design simple.

🧱

Reuse existing designs/code

Benefit from prior investment in reusable components. The source explicitly says cloning is not good reuse.

🪢

Design for flexibility

Anticipate change, reduce coupling, increase cohesion, create abstractions and avoid unnecessary hard-coding.

⏳

Anticipate obsolescence

Avoid fragile dependencies on early, undocumented, environment-specific or poorly supported technologies.

🌍

Design for portability

Avoid facilities tied unnecessarily to a single environment when broader platform support is required.

🧪

Design for testability

Make functionality drivable by external test programs without requiring the GUI; automate testing where possible.

Reuse warning

Copying is not the same as reuse

✕ Clone code

The same logic exists in several places; every defect fix or change must be repeated across clones.

→

✓ Reusable design/component

One maintained abstraction or component is deliberately designed so multiple contexts can use it.

Source-specific guidance

Concrete rules worth remembering

🚫Avoid fragile technology choices

Early releases, undocumented features and little-used library features increase obsolescence risk.

🏢Think about vendor longevity

The source cautions against specialized technology from suppliers unlikely to provide long-term support.

📐Prefer standards

Standard languages and technologies with multiple-vendor support can reduce future lock-in.

☕Testability example

The lecture suggests a Java main() method as a simple way to exercise other methods without relying on a GUI.
