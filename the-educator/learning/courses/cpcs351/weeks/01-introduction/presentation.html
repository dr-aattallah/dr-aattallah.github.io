The Nature of Software

Software is fundamentally different from physical products. Understanding those differences explains why disciplined software engineering is necessary.

The Software Iceberg

What users seeScreens, features, responses, workflows and releases — the visible product experience.
What engineers manageRequirements, architecture, design decisions, dependencies, data, quality, coordination, change, testing and evolution.
The important ideaThe visible interface is only a small part of the engineering effort. Much of software complexity exists below the surface and must remain consistent as the system changes.
Must Know

Why software is different

IntangibleSoftware cannot be physically inspected like a building or manufactured product. Progress, structure and quality are therefore harder to see directly.
Easy to reproduceOnce developed, another copy costs almost nothing. Most economic cost lies in understanding, designing, building and validating the original system.
Labor-intensiveSoftware development depends heavily on human reasoning, communication, design and problem solving; much of this intellectual work cannot simply be automated away.
Easy to modifyCode can be edited quickly, but a local modification can create consequences in requirements, architecture, data, security, testing and operations.
Engineering Consequences

Easy to modify does not mean easy to change safely

Local changeA developer may alter only a few lines of code.
System impactThe change may affect assumptions and behavior in several other components.
Quality impactExisting tests, security rules, performance or data integrity may need to be reconsidered.
Engineering responseTraceability, design discipline, reviews and testing help teams understand and control change.
Must Know · Continued

Working code is not enough

A program can work and still be poor softwareCorrect-looking output does not guarantee maintainability, security, reliability, usability, scalability or a sound design.
Software does not physically wear outUnlike mechanical products, software does not degrade because material parts wear down.
So why can software deteriorate?Repeated modifications can increase complexity, introduce inconsistencies, break design assumptions and make future changes increasingly difficult and risky.
Software Economics

Key Takeaway

Why do we need software engineering?

Software is intangible, inexpensive to reproduce, labor-intensive to create, highly changeable, and does not physically wear out. These characteristics make software powerful — but they also make complexity and change difficult to control. Disciplined software engineering provides the methods needed to build, coordinate, verify and evolve software safely.
