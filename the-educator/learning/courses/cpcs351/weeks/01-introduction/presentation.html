The Nature of Software

Software is fundamentally different from physical products. Understanding those differences explains why disciplined software engineering is necessary.

Core QuestionWhy can software be expensive and difficult even though it has no factory, raw material, or physical wear?
Learning FocusRecognize software's distinctive properties and connect each one to an engineering consequence.

The Software Iceberg

What users see

Screens, features, responses, workflows and releases — the visible product experience.

What engineers manageRequirements, architecture, design decisions, dependencies, data, quality, coordination, change, testing and evolution.
The important ideaThe visible interface is only a small part of the engineering effort. Much of the complexity exists below the surface.
Must Know

Why software is different

01 · IntangibleSoftware cannot be physically inspected like a building. Progress, structure and quality are harder to see directly.
02 · Easy to reproduceOnce developed, another copy costs almost nothing. Most cost lies in understanding, designing, building and validating the original system.
03 · Labor-intensiveDevelopment depends heavily on human reasoning, communication, design and problem solving.
04 · Easy to modifyCode can be edited quickly, but a local modification can affect requirements, architecture, data, security, testing and operations.
Engineering Consequences

Easy to modify ≠ easy to change safely

1
Local ChangeA developer may alter only a few lines of code.
2
System ImpactOther components may depend on the changed behavior.
3
Quality ImpactTests, security, performance and data integrity may be affected.
4
Engineering ResponseTraceability, reviews and testing help control the change.
Must Know · Continued

Working code is not enough

It works!

Correct-looking behavior alone does not prove that the software is maintainable, secure, reliable, usable or scalable.

Software does not physically wear outUnlike mechanical products, software does not degrade because material parts wear down.
But software can deteriorateRepeated modifications can increase complexity, create inconsistencies and break design assumptions.

Key Takeaway

Why do we need software engineering?

Software is intangible, inexpensive to reproduce, labor-intensive to create, highly changeable, and does not physically wear out. These characteristics make software powerful — but they also make complexity and change difficult to control. Disciplined software engineering provides the methods needed to build, coordinate, verify and evolve software safely.
