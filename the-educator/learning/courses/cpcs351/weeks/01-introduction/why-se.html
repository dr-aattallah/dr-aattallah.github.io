Topic 01 · Lesson 03

Why Software Engineering?

As software spreads, grows, and becomes expensive and critical, “just code it” stops being a viable development strategy.

3of 8 lessons
Scale changes the problemCould one engineer build a 500,000-line system alone in a reasonable time?
Learning Focus

Justify the need for software engineering using the chapter's arguments about societal dependence, cost, complexity, embedded systems, scale, and teamwork.

Must Know

Why an Engineering Approach Is Needed

  • Software is expanding into all sectors of society; companies rely on it to run and expand their businesses.
  • Systems are becoming larger and more complex, reaching millions of lines of code.
  • The chapter notes that software can represent 90–95% of total system costs, compared with 5–10% two decades earlier.
  • Embedded systems may contain costly application-specific integrated circuits (ASICs), making software quality critical.
Visual Anchor · The Scale Argument
10,000 LOC

100–200 engineer-days
≈ 5–10 months for one engineer

→
500,000 LOC

5,000–10,000 engineer-days
≈ 20–40 years for one engineer

Conclusion: real-world systems require many software engineers working together.

Official Evidence

50–100 Lines per Day Is Not “Slow Typing”

The chapter uses an average of 50–100 source lines per day to make a larger point: engineering time includes understanding, design, coordination, testing, correction and integration—not merely typing code.

Estimate Before You Memorize

If a system is fifty times larger, why can't we simply expect one engineer to finish it fifty times faster by using better typing tools?

Self-feedback: Scale adds intellectual complexity and forces teamwork. Teamwork then introduces conceptualization, communication and coordination problems—the subject of the next lesson.
