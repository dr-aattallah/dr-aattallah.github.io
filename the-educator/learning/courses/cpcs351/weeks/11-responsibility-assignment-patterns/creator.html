Lesson 06

The Creator Pattern

Object creation is itself a responsibility. Assign it where the relationship or required construction information already exists.

6of 8 pages

Who should create object A?

Assign class B responsibility for creating an A when one or more of these relationships applies:

  • B is an aggregate of A objects.
  • B contains A objects.
  • B records A objects.
  • B closely uses A objects.
  • B has the information needed to create A.

Chapter examples

Book → Chapter
Book creates Chapter because a chapter is a part of a book.
CheckoutController → Loan
The controller can create Loan when it has the constructor information required by the checkout interaction.
Dispenser → VendingItem
The chapter uses containment/recording examples to motivate creator assignment.

Benefits and related patterns

Creator supports low coupling because creation is assigned where coupling often already exists, and it can increase reusability. The chapter relates Creator to Low Coupling and to creational patterns such as Abstract Factory, Factory Method, Builder, Prototype and Singleton, as well as Composite.

Added examples

Order → OrderLine because Order contains/records its lines. Course → Section when Course aggregates its offered sections. ShoppingCart → CartItem because Cart contains and closely uses CartItems.
