Quality Measurements & Metrics

Turn quality claims into quantitative evidence using measurements and metrics across requirements, design, implementation and object-oriented software.

6of 9 pages
HookIf a manager says “quality improved,” what evidence would make that statement more than an opinion?

Measurements turn vague claims into evidence—but only if we understand what each metric actually measures.

Learning Focus

Define measurement and metric, identify the complete R/D/C/S metric categories from the lecture, and interpret representative requirements, design, implementation, and OO metrics.

Measurement vs. Metric

Software measurements are objective, quantitative assessments of software attributes. Metrics are standard measurements. Software quality metrics are standard measurements of software quality.

Complete Lecture Taxonomy

Four Families of Software Quality Metrics

R · RequirementsUnambiguity, Completeness, Correctness, Consistency.
D · DesignFan-In, Fan-Out, Cohesion, Coupling, Modularity, Module Design Complexity, Design Complexity.
C · ImplementationDefects/KLOC, documentation/KLOC, comment lines/LOC, cyclomatic complexity.
S · System / OOWeighted methods/class, inheritance depth, number of children, class coupling, response for a class, lack of cohesion in methods.
Requirements Metrics — Complete List
  • Unambiguity: degree to which requirements have a single clear interpretation.
  • Completeness: degree to which required information and behavior are specified.
  • Correctness: degree to which requirements accurately represent what is required.
  • Consistency: degree to which requirements do not conflict with one another.
Ambiguous
“The system should respond quickly.”
→
More measurable
“For the specified workload, 95% of responses shall complete within 2 seconds.”

The rewritten statement is an explanatory example: it shows how a vague quality claim can become easier to verify and measure.

Design Metrics — Definitions from the Lecture
  • Fan-In: number of modules that call a given module.
  • Fan-Out: number of modules called by a given module.
  • Cohesion: relevance of functions in a module to its core functionality.
  • Coupling: data dependencies among modules.
  • Modularity: high cohesion and low coupling lead to high modularity.
  • Module Design Complexity: integration tests required to integrate a module with subordinate modules.
  • Design Complexity: number of subtrees in structure charts with module M as root.

One focused responsibility; few external dependencies
↔
Module B
Many unrelated responsibilities; many dependencies

Module A illustrates the direction associated with stronger modularity: higher cohesion and lower coupling.

Implementation Metrics — Complete List
  • Defects/KLOC: defects normalized by thousand lines of code.
  • Pages of documentation/KLOC: documentation volume normalized by code size.
  • Comment lines/LOC: comment density relative to source code.
  • Cyclomatic complexity: number of independent control-flow paths in a function (McCabe, 1979).

Example: two modules may contain the same LOC but differ greatly in cyclomatic complexity; size alone therefore does not describe control-flow complexity.

Object-Oriented / System Metrics — Complete List
  • Weighted methods per class.
  • Depth of inheritance tree.
  • Number of children.
  • Coupling between object classes.
  • Response for a class.
  • Lack of cohesion in methods.

Example: a class with many unrelated methods may show weak cohesion even when it compiles and passes basic functional tests. Metrics provide a signal for investigation; they do not replace engineering judgment.

Common Misconception

“A number is automatically a quality metric.” A metric is useful only when the measured attribute, definition, context, and interpretation are clear.

Interpret, Don’t Just Count

Two modules have equal size. A has high cohesion and low coupling; B has low cohesion and high coupling. Which is more modular?

Self-Feedback: Module A. The lecture explicitly links high cohesion + low coupling with high modularity.
