Topic 02 · Lesson 04

Static & Dynamic V&V Across the Life Cycle

See how quality evidence follows artifacts from requirements through operation.

4of 9 pages
HookHow can you find a serious defect before the software even runs?

By examining static representations: requirements, designs, code, test data, and other artifacts.

Learning Focus

Explain static versus dynamic V&V and map appropriate quality activities across the software life cycle.

Static

Review, walkthrough, inspection, peer review, and desk checking analyze a static representation to detect problems without executing software.

Dynamic

Testing executes the product and observes its behavior to check results and uncover failures.

The lecture emphasizes three simultaneous concerns: development activities must be carried out correctly; artifacts such as the SRS, design, and code must be checked; and integrated software must execute and produce expected results.

Map the Technique

You have only a requirements document—no code exists yet. Which quality activities are still possible?

Self-Feedback: Static techniques are already possible: review, inspection, walkthrough, or peer review of the requirements. Quality assurance begins before executable software exists.
