Finding Candidate Use Cases

Requirements often contain verb–noun phrases that reveal domain tasks, but candidates must still be validated.

3of 9 pages
Core lecture content Clarification & study aids
Learning focus

Use UML use-case notation and style to depict high-level user requirements and write use-case-centric functional specifications.

Core lecture

What you need to understand

  • Look for domain-specific “do something,” “something must be done,” or “perform some task” phrases.
  • Extract the actor and the system/subsystem containing the behavior.
  • Technical actions such as Query Database, Press Submit Button, or Search Linked List are usually steps or implementation details, not complete actor goals.

Worked example

Library

“Allow a patron to return documents” → Patron + Return Document. “Update database row” is not a patron goal.

Remember

Find domain goals first; reject UI clicks and internal computation as top-level use cases.
