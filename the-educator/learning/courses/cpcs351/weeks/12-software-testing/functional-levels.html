Lesson 03

Functional, Nonfunctional & Testing Levels

Distinguish what is being evaluated from the level at which the software is being evaluated.

3of 8 pages

Functional testing

The lecture presents functional testing as black-box testing based on software specifications. Inputs are supplied and outputs are compared with intended functionality. Its five-step flow is: determine intended functionality → create test data from specifications → determine expected output → write scenarios/execute cases → compare actual and expected results.

Non-functional testing

Non-functional testing evaluates non-functional attributes and requirements such as performance, security, and user interface.

Added teaching noteThe CLO names four testing levels, but the detailed slides mainly elaborate unit testing and testing techniques.

The distinctions below are added for CLO alignment.

Four levels

Unit
Test an individual function/class/component in isolation.
Integration
Test whether combined units/components interact correctly.
System
Test the integrated system as a whole against system requirements.
Acceptance
Evaluate whether the system is acceptable for its intended users/customer and use.

Added example — registration system

Unit: test prerequisite-check logic. Integration: verify RegistrationService communicates correctly with Student and Section repositories. System: exercise the full registration workflow. Acceptance: verify the delivered workflow satisfies registrar/student expectations.
