Test Planning, Test Cases & Defect Reporting

Plan the testing work, turn requirements into repeatable test cases, and report defects clearly enough that another person can reproduce and fix them.

Strategy → Plan → Case

Test Strategy asksWhich methods and levels? Which risks first? What environment, metrics, automation approach, and standards?
Test Plan asksWhat is in/out of scope? Who tests? When? With what environment/data? What are pass/fail and exit criteria?

Manual or automated?

Manual

Flexible and useful for exploration, new UI behavior, and situations that need human judgment.

Example: usability observation with first-time students.
+
Automation

Best when a stable test is repeated frequently and consistency/speed provide value.

Example: run the login regression suite after every build.
Automation decision: Favor repeatable, important, stable tests. Automation does not replace test design; it automates execution of selected tests.
