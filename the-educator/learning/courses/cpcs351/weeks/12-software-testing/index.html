THE TESTING MINDSET

Do not ask “Did we test it?” Ask “What evidence do we have?”

Every useful test connects a requirement or risk to a deliberate input, an expected result, an observed result, and a decision.

Why do we test?

✓Demonstrate satisfactionShow that functional and non-functional requirements are met under selected conditions.
⌕Detect problemsExpose errors, missing requirements, gaps, and undesired behavior before users discover them.

Testing answers release questions

Correct?Does it work as expected?
Useful?Does it meet user needs?
Compatible?Does it work with other systems?
Ready?Is the evidence strong enough to release?
Fast?How does it perform?
Scalable?What happens as users increase?
Secure?Can misuse expose weaknesses?
Complete?Which areas still need work?

A test is a small experiment

Requirement / risk→Test condition→Input→Expected result→Actual result→Evidence
Important: A passed test provides evidence for the specific situation tested. It does not prove that the software contains no defects.
