Lesson 04

Performance, Load, Stress, Security & Portability

Quality is more than correct output: speed, capacity, stability, security and deployability also need evidence.

4of 8 pages

Performance testing

Performance testing looks for bottlenecks and performance issues. The lecture identifies causes such as network delay, client-side processing, database transaction processing, server load balancing and data rendering. Key aspects are speed/response time, capacity, stability and scalability.

Load vs stress

Load testing
Observe behavior under normal/peak load and large input; identify maximum capacity and peak-time behavior.
Stress testing
Test abnormal conditions, reduced resources, or load beyond the actual limit.

Security testing

The lecture includes confidentiality, integrity, authentication, availability, authorization and non-repudiation, plus vulnerability concerns such as input validation, SQL/injection flaws, session management, cross-site scripting, buffer overflows and directory traversal.

Portability & documentation

Portability testing checks that software can be moved/reused across computers or platforms. Testing documentation helps estimate effort and coverage and supports requirement tracing. Artifacts listed are Test Plan, Test Scenario, Test Case, and Traceability Matrix.

Added example — exam registration peak

Thousands of students registering at 8:00 AM is a load question. Intentionally exceeding expected concurrency or removing resources is a stress question. Measuring response time and stability across both is part of performance evidence.
