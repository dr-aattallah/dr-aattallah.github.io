Nonfunctional Testing & Documentation

Correct functionality is not enough. Software must also provide evidence about performance, resilience, security, portability, and traceability.

Performance: four questions

SpeedHow fast is the response?
CapacityHow much work can it handle?
StabilityDoes behavior remain reliable over time?
ScalabilityWhat happens as demand grows?

Potential bottlenecks include network delay, client-side processing, database transactions, server load balancing, and data rendering.

Load vs Stress

Load Testing

Observe behavior under normal and peak expected loads and large input volumes.

“Can it handle what we expect?”
VS
Stress Testing

Push beyond expected limits or reduce resources to create abnormal conditions.

“What happens when expectations are exceeded?”

Security testing: protect the system and its data

Security propertiesConfidentiality · Integrity · Availability · Authentication · Authorization · Non-repudiation
Input & session risksInput validation · Injection flaws · SQL injection · Session management
Application risksCross-site scripting · Buffer overflows · Directory traversal · known/unknown vulnerabilities

Portability & testing documentation

Portability testing checks whether software can be moved or run across computers/platforms. Documentation makes the testing work visible, repeatable, estimable, and traceable.

Test PlanScope, approach, resources, schedule.
Test ScenarioA behavior or situation to evaluate.
Test CaseInputs, steps, expected result, actual result.
Traceability MatrixConnect requirements to test evidence.
Scenario: Thousands of students registering at 8:00 AM is a load question. Intentionally exceeding expected concurrency or removing resources is a stress question.
