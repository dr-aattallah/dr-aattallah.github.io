Use this page as your study checkpoint. First identify the testing question, then select the level, method, technique, document, or follow-up activity that fits.

Diagnose the testing problem

1 · Username must be 6–10 characters.

EP: 0–5 invalid, 6–10 valid, 11+ invalid. BVA: 5, 6, 10, 11.

2 · Tester sees only inputs and outputs.

Black-box testing.

3 · Developer investigates branches inside code.

White-box knowledge. If locating and fixing a failure's cause, that work is debugging.

4 · Checkout depends on member? coupon? stock?

Decision Table Testing because behavior depends on combinations of conditions.

5 · 5,000 users are the expected peak.

Load testing. Going deliberately beyond the expected limit is a stress test.

6 · Test communication between two services.

Integration testing.

7 · Customer decides whether delivered system is acceptable.

Acceptance testing.

8 · Requirement must be linked to evidence.

Use a Traceability Matrix to connect requirements to tests.

9 · A fixed password-reset defect is tested again.

Testing the exact failed scenario is re-testing. Re-running related login/session tests is regression testing.

10 · Team reviews requirements before coding.

Verification. Running the implemented system against user needs is validation.

11 · Tester freely explores checkout and adapts based on discoveries.

Exploratory testing.

12 · App works in Chrome but fails in Safari.

Compatibility/configuration testing.

Worked study set · Smart Course Registration

A course accepts 1–40 students. Registration requires prerequisite completion and an available seat. Thousands of students may access the system at opening time, and the same system must work in multiple browsers.

EPCapacity partitions: ≤0 invalid · 1–40 valid · ≥41 invalid.
BVAValues: 0, 1, 40, 41.
Decision TablePrerequisite × seat availability determines add/reject action.
IntegrationRegistrationService ↔ Student/Section data sources.
Load / StressExpected opening traffic vs deliberately exceeding capacity.
CompatibilityRepeat critical workflow on Chrome, Safari, and mobile browser.

Mini exam-style questions

A field accepts age 18–65. Give EP and BVA.

EP: <18 invalid, 18–65 valid, >65 invalid. BVA: 17, 18, 65, 66.

A payment fix is confirmed, but cart totals now fail. What happened?

The original fix may pass re-testing, but the cart failure is a regression that should be detected by regression testing.

A typo is visible on tomorrow's launch page. Low severity or low priority?

Likely low severity but possibly high priority because it is highly visible and release is imminent.

Final study mindset: Do not memorize a list of testing names. For every scenario ask: What is the scope? What risk or behavior matters? What input structure exists? What evidence is needed? What should happen after a defect is found?
