Choose the Test from the Problem

A strong tester does not start with a favorite technique. Read the risk or requirement, recognize the testing question, then choose the evidence that fits.

One-minute testing map

Scope?Unit → Integration → System → Acceptance
Visibility?Black → Grey → White Box
Input domain?Regions → EP
Edges → BVA
Combined logic?Conditions + actions → Decision Table
Quality attribute?Performance · Load · Stress · Security · Portability
Failure found?Testing exposes it → Debugging isolates and fixes the cause

Diagnose the testing problem

1 · Username must be 6–10 characters.

EP: 0–5 invalid, 6–10 valid, 11+ invalid. BVA: 5, 6, 10, 11.

2 · Tester sees only inputs and outputs.

Black-box testing.

3 · Developer investigates branches inside code.

White-box knowledge. If locating and fixing a failure's cause, that work is debugging.

4 · Checkout depends on member? coupon? stock?

Decision Table Testing because the outcome depends on combinations of conditions.

5 · 5,000 users are the expected peak.

Load testing. If you deliberately go beyond expected limits, it becomes a stress question.

6 · Test communication between two services.

Integration testing because the focus is interaction between combined units/components.

7 · Customer decides whether delivered system is acceptable.

Acceptance testing.

8 · Requirement must be linked to evidence.

Use testing documentation and a Traceability Matrix to connect requirements to tests.

Final challenge · Smart Course Registration

A course accepts 1–40 students. Registration requires prerequisite completion and an available seat. At registration opening, thousands of students may access the system simultaneously.

Input ruleUse EP/BVA for capacity-related numeric boundaries.
Business logicUse a decision table for prerequisite × seat availability.
Operational riskUse load/performance testing for registration-opening demand.
Testing mindset: Do not choose test data randomly. Every test value should exist for a reason: represent a partition, challenge a boundary, cover a condition combination, exercise a testing level, or provide evidence for a quality requirement.
