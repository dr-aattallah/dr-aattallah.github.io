Concepts You Must Distinguish

These concepts appear across the two course sources and are easy to confuse in exams. Learn them by contrast and by scenario, not by memorizing isolated definitions.

Quality Assurance vs Quality Control

Quality Assurance (QA)

Focuses on preventing defects by improving and following processes, standards, templates, reviews, and readiness activities.

Process-oriented · Prevent
VS
Quality Control (QC)

Focuses on evaluating the product and identifying whether it meets required quality and performance expectations.

Product-oriented · Detect
Example · Which is QA and which is QC?

Defining a mandatory code-review checklist is QA. Executing tests on the completed feature to find failures is QC/testing.

Verification vs Validation

Verification

Review requirements, designs, code, plans, or specifications to check that the product is being built according to defined artifacts.

“Are we building it correctly?”
VS
Validation

Execute/evaluate the software to check that the delivered behavior satisfies intended requirements and user needs.

“Are we building the right product?”
Example · Course Registration

Reviewing the registration requirement for completeness is verification. Running the system and confirming that eligible students can register correctly is validation.

Re-testing vs Regression Testing

Re-testing

Run the failed scenario again after a fix to confirm that the original defect is actually corrected.

Did we fix this defect?
+
Regression Testing

Run relevant existing tests after a change to detect new problems introduced elsewhere.

Did the fix break something else?
Example · Login fix

A password-reset bug is fixed. Running the same reset scenario is re-testing. Re-running login, account lockout, session, and profile-access tests is regression testing.

Exploratory, Usability & Compatibility Testing

Exploratory TestingThe tester learns and adapts while testing instead of following only a fixed script.
Example: freely explore checkout after noticing unusual cart behavior.
Usability TestingObserve whether intended users can complete tasks effectively and understand the interface.
Example: ask a new student to register for a course without help.
Compatibility / ConfigurationCheck behavior across browsers, operating systems, devices, or configurations.
Example: Safari vs Chrome, mobile vs desktop.

Testing terms: error, defect, failure

Error
human/mismatch mistake→Defect
flaw in software/artifact→Failure
observable incorrect behavior
Example · Discount calculation

A developer writes the wrong formula (error). The wrong formula remains in the code (defect). A customer receives a wrong total during checkout (failure).

Study rule: When two terms look similar, ask what they focus on: process or product, artifact or execution, original defect or side effects, scripted or adaptive testing.
