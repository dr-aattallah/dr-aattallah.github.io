08 · BLACK-BOX TEST DESIGN

Decision Table Testing

When behavior depends on combinations of conditions, turn the logic into explicit rules so missing combinations become visible.

CONDITIONS → RULES → ACTIONS

Complicated logic becomes a table you can test systematically.

Decision tables document condition combinations and the expected action for each rule.

Email + password example

Condition / RuleR1R2R3R4
Email present?FTFT
Password present?FFTT
Expected actionEnter emailEnter passwordEnter emailLogin processed
Two independent Boolean conditions produce 2² = 4 combinations.

Diagnose the technique

If a discount depends on member?, coupon?, and order ≥ 200?, use a decision table because the outcome depends on combinations. With three independent Boolean conditions, start by considering 2³ = 8 combinations.

Recognition cue: If the requirement contains several IF/AND/OR conditions that combine to produce different actions, think Decision Table.
