Cause–Effect & Decision Table Testing

When multiple conditions combine, enumerate meaningful combinations and map each rule to an expected action.

7of 8 pages

Technique set in the lecture

The lecture lists three black-box techniques: Equivalence Partitioning, Boundary Value Analysis, and Cause–Effect Testing. Its final slides then teach Decision Table Testing as a way to document complicated logic, test combinations of conditions, and connect conditions to actions.

Added example — course add request

Conditions: Prerequisite satisfied? and Seat available? Four rules cover all combinations. Only T/T produces “Add course”; the other rules produce a reason for rejection or next action.

When to use a decision table

Use it when behavior depends on combinations of conditions and you want to make missing combinations visible.
