Process and Methodology

A process gives the development journey its structure. A methodology tells the team how to perform the work inside that structure.

1of 11 pages
Core lecture content Clarification & study aids
Learning focus

Distinguish software process from methodology and explain how phases, artifacts, milestones, criteria, steps and techniques work together.

Core lecture

Route versus recipe

🗺️ Process = what & when

A set of interrelated activities carried out in phases. Activities produce artifacts; phase completion establishes milestones; artifacts can become inputs to later work.

🧭 Methodology = how

An implementation of a process or phase that specifies the detailed steps, representations, procedures, techniques and flows used to perform the work.

Methodology anatomy

What makes “how” precise?

📥InputWhat enters the step?
🚪Entry CriteriaWhen may work begin?
🛠️Steps & TechniquesHow is work performed?
📦Artifact / OutputWhat is produced?
✅Exit CriteriaWhen is the step complete?
Software example: Requirements analysis may begin when stakeholder scope is available, apply interviews/modeling techniques, produce a requirements specification or models, and exit when agreed quality and review criteria are satisfied.
Worked analogy

Building permit

The process defines stages such as submit → review → approve. The methodology defines the forms, checklist, representations, review procedure, acceptance criteria and handoffs used inside each stage.

Memory hook

Process = lifecycle structure. Methodology = execution detail. Good engineering needs both.

Exam lens

Distinguish nearby concepts

If the question asks...

Which phases happen, what artifacts flow between them, or where milestones occur → think process.

If the question asks...

Which steps, procedures, techniques, representations or entry/exit conditions are used → think methodology.
