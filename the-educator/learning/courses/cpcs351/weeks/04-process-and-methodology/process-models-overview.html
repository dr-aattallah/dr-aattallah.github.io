Process Models Overview

The same project can be organized using different process logics. The model changes when feedback, commitment, and risk are handled.

3of 11 pages
Core lecture content Clarification & study aids
Learning focus

Describe the different software development models: waterfall, prototype, evolutionary, spiral, and agile.

Core lecture · five process logics

Five ways to organize development

Each model answers the same question differently: when should the team commit, learn, reduce risk, and deliver? Use the visual hook on each card to remember its dominant logic.

Waterfall

Major development phases proceed in a planned sequence, with strong emphasis on completing one stage before the next.

Sequence

Prototype

Build a model early to expose unclear requirements, test ideas, and learn before committing to the full solution.

Learn

Evolutionary

Working versions grow progressively; each version extends or improves the system that will eventually become the production product.

Grow

Spiral

Development proceeds through repeated loops driven by identifying, analyzing, and reducing the most important risks.

Reduce Risk

Agile

Work is organized into short repeated delivery and feedback cycles so the team can adapt as needs and priorities change.

Adapt
Memory hook: Waterfall flows → Prototype learns → Evolutionary grows → Spiral de-risks → Agile adapts.
Worked example

Campus mobile app

Stable regulatory reporting may suit plan-driven work; uncertain student workflows benefit from prototypes and iterative delivery.

Remember

Choose a model by the problem’s uncertainty, risk, coordination, and feedback needs—not by fashion.
