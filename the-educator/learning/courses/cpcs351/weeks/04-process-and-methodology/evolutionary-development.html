Evolutionary Development

Build something useful, learn from real use, and let the production system grow through successive versions.

6of 11 pages
Core lecture content Clarification & study aids
Learning focus

Explain how working versions evolve toward production, distinguish evolution from throwaway prototyping, and recognize the engineering debt uncontrolled growth can create.

The trade-off: rapid evolution improves learning and flexibility, but ad-hoc growth can make the process hard to trace, weaken structure, increase tool dependency and make documentation expensive.

Critical distinction

Prototype or evolving product?

🗑️ Throwaway Prototype

Build → learn → discard. Keep the knowledge, not the prototype.

🌳 Evolutionary Development

Build → learn → improve → production. Keep and strengthen the working system.

Worked example

Research analytics tool

Scientists begin with dataset upload and one analysis, then add visualizations, collaboration and automation across working releases. As capability grows, the team must deliberately refactor architecture and maintain documentation so the evolving prototype does not become a fragile production system.

Memory hook · 🌱→🌳

Evolution means growth, not replacement. Flexibility is valuable only when engineering discipline grows with the product.
