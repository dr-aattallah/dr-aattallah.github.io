Software Paradigms

A paradigm is a way of seeing the software problem. Change the lens, and the same system is organized around different primary ideas.

Learning focus

Distinguish procedural, object-oriented and data-oriented paradigms, and explain how a paradigm shapes system conceptualization without being the same thing as a methodology.

Three lenses on the same reality

Worked comparison · Library system

One problem, three mental models

⚙️ Procedural view

Organize around procedures such as checkOutBook(), returnBook() and calculateFine().

🧱 Object-oriented view

Organize around objects such as Patron, Book, Loan and the responsibilities connecting them.

🗃️ Data-oriented view

Organize around book, patron and loan data, their schemas, movement and transformations.

Paradigm ≠ Methodology

Do not mix the worldview with the work process

👓 Paradigm

A conceptual lens: how developers view and structure the software reality.

→
🧭 Methodology

A structured way of organizing development work, activities and practices within or across paradigms.

A methodology can draw from a paradigm, but the two terms are not interchangeable. Object-oriented is a paradigm; Scrum, for example, is a development framework/method—not a software paradigm.

Memory hook

Paradigm = lens. Methodology = route. The lens changes how you see the problem; the methodology changes how you organize the work.
