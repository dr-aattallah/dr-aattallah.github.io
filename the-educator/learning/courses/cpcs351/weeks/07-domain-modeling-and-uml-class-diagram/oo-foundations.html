OO Foundations: Objects, Classes, Attributes & Operations

Domain modeling uses object-oriented concepts to describe the problem world before detailed software design begins.

4of 14
Learning focus

Distinguish object, class, attribute, operation, and encapsulation and explain why objects are the starting point in the OO paradigm.

OO paradigm

The world is viewed as interacting objects

🧍Object

An instance of a class; a concrete entity in the modeled domain.

🏷️Class

A type: an abstraction and intentional definition of objects with similar properties and behavior.

📌Attribute

Defines a property of a class of objects.

⚙️Operation

Defines behavior of a class of objects.

Class ≠ Object

Class

Student

A type describing what Student objects have in common.

Object

student #2339663

One particular instance of the Student class.

Attributes

id, name, program

Operations

Behavior belongs to the class concept, but domain models normally omit operations.

Encapsulation

Keep properties and behavior together

The lecture defines encapsulation as defining/storing together the properties and behavior of a class or object. This helps us think about a class as one coherent concept rather than disconnected data and functions.

Remember

Objects exist; classes describe meaningful kinds of objects. In the domain model we focus on domain classes, their attributes, and their relationships.
