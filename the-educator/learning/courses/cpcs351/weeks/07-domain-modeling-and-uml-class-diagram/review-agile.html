Review, Agile Modeling & Exam Checklist

Finish by inspecting the model for correctness, simplicity, shared understanding, and usefulness.

14of 14
  • Work closely with customers and users to understand the application and application domain.
  • Perform domain modeling only if needed; keep it simple and expand incrementally.
  • Domain modeling may occur alongside actor-system interaction, object interaction, object state, and activity modeling.
  • Review and modify the diagram to reflect corrections and comments from team members.
  • Check that classes are domain concepts, attributes are properties, and relationships express actual domain facts.
  • Check inheritance with IS-A and conformance tests.
  • Check every association end for meaningful multiplicity.
  • Check aggregation/composition for real ownership and lifecycle semantics.
  • Remember the lecture distinction: UML class diagrams describe information structure and relationships; use cases show the user view/functions; sequence, activity, state, and package diagrams answer different questions.
1Concepts correct?
2Attributes belong?

4Multiplicities justified?

Remember

A good domain model is useful and correct enough to guide the next decision—not maximally detailed.
