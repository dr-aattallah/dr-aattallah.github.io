Lab 07 · Behavioral Modeling

Sequence, Activity & State Diagrams

Represent three different dimensions of behavior: interactions over time, workflows and decisions, and the lifecycle of stateful objects or systems.

SequenceActivityState MachineInteractions
Learning outcomeDepict sequence, activity and state-machine diagrams using a UML tool.
SequenceShows ordered messages/interactions among participating objects for a scenario.
Activity & StateActivity models workflow/control; state machine models states, events and allowed transitions.

Three behavioral views

Sequence Diagram

Use it to show how actors/objects collaborate over time to realize a use case or scenario, including messages and system responses.

Activity Diagram

Use it to model processing flow, branching, data/control movement, concurrency, forks and joins.

State Machine Diagram

Use it when an object or system has meaningful states whose status determines what events and processes are allowed.

Guided examples in the source lab

  1. Blood Donor Centre sequence: donation, testing, processing, distribution and destruction of contaminated units.
  2. Reserve a Car sequence: derive interactions from a use case whose precondition is that the customer is logged in.
  3. Blood Distribution state model: fulfill hospital requests or wait for future donation batches until quantities become available.
  4. Digital watch state model: display, set-hours and set-minutes modes controlled by A/B buttons.
  5. Print report activity: identify action states and transitions for a project manager printing a report.
  6. Purchasing activity: model requests below/above $1,500, vendor bids, selection and purchase-order flow.

Additional practice and case study

Model the elevator-door scenario as a sequence diagram using Passenger, Floor Button, Elevator Controller, Elevator and Door.
Create state machines for a multi-button magnifying mouse and for a two-battery charger with idle, discharging and charging modes.
Real Estate MLS case: develop the Add a Listing use-case description, activity diagram and abbreviated class diagram, including trigger, actors, stakeholders, pre/postconditions, normal flow and exceptions.
