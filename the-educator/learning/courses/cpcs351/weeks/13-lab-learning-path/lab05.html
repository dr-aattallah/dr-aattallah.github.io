Lab 05 · System Boundary & Services

Use Case & Context Diagrams

Translate narrative requirements into two complementary views: a context view of the system and its environment, and a use-case view of actors and the functionality the system must provide.

Learning outcomeUse a UML CASE tool to create analysis diagrams from a software problem.

Context diagram

A context diagram defines the boundary between the system and its environment. It provides a high-level picture of the system, external entities that interact with it, and the nature of those interactions. It helps teams agree scope, identify external interfaces and establish a shared understanding before detailed modeling.

Use Case Diagram

A use-case model captures intended system functionality from the perspective of external actors. The diagram communicates the system’s services, surroundings and relationships between actors and use cases. The lab expects students to derive these elements from prose rather than copy them from a prepared list.

Four modeling problems

1 · Exam process
Model an instructor preparing/administering an exam and the special makeup-test case.
2 · Alarm clock
Identify the top-level functional requirements for a configurable clock with 12/24-hour display, one or two alarms, stop, snooze, configurable snooze delay and automatic shutoff after two minutes; represent them with a use-case diagram.
3 · Cash dispenser
Draw a context diagram for a system with Receive Request, Check Password, Withdraw and Show Balance processes.
4 · Retail clothing store
Draw a context diagram showing the customer payment/receipt interaction and the management-report interaction with the store manager.
