Lab 09 · Responsibility Design

Design Patterns & GRASP

Move beyond drawing correct diagrams to assigning responsibilities deliberately. Explore Singleton and GRASP patterns—Controller, Information Expert and Creator—and evaluate how they affect coupling and design quality.

SingletonControllerExpertCreatorGRASP
Learning outcomeApply design patterns appropriately to enhance the design/domain model.
ToolsThe source uses NetBeans IDE 8.2 plus a UML-supporting tool.
Pattern mindsetA pattern is a reusable solution approach, not finished code or a design to copy blindly.

Why patterns?

Design patterns provide shared terminology and accumulated design experience for recurring problems. The source groups the classic patterns into creational patterns concerned with object creation, structural patterns concerned with class/object composition, and behavioral patterns concerned with communication among objects.

Practice sequence

Singleton · KAU President
Model the office as a single globally accessible instance. The checklist requires a private static instance, public static accessor, lazy initialization, private/protected constructors and client access through the accessor.
Controller · Checkout Document
Inspect the provided sequence design, identify its problems, then improve it by assigning actor-request handling to an appropriate controller.
Information Expert · Reset Password
Realize the use case by assigning responsibility to the object that owns the information required to fulfill the request.
Creator
Decide which object should create another object based on responsibility and structural relationships.
Integrated reflection
Explain how Controller, Expert and Creator improve the behavioral design of the UML Class Diagram Editor compared with a design that ignores these patterns.

Design reasoning to retain

Patterns should improve a real design concern: responsibility clarity, lower coupling, stronger cohesion, controlled creation or consistent access. The goal is not to insert pattern names into a diagram; it is to explain why the chosen responsibility assignment is better.
