Lab 03 · Problem Discovery

Domain Analysis, Problem & Scope

Before writing requirements, learn the world in which the software will operate. Identify information sources and stakeholders, capture essential domain knowledge, define the problem precisely and set a realistic system boundary.

Domain AnalysisProblem StatementScopeStakeholders
Learning outcomesDefine a problem statement, scope and relevant stakeholders; write a concise domain-analysis document.
Why it mattersGood domain understanding supports faster development, a better system and better anticipation of extensions.
RequirementsNo specific software tool is required.

Domain analysis

Domain analysis is the process through which a software engineer learns enough about the client’s field of business or technology to understand the problem. A domain expert is someone with deep knowledge of that field.

Recommended domain-analysis document

  1. Introduction
  2. Glossary
  3. General domain knowledge
  4. Customers and users
  5. Environment
  6. Current tasks and procedures
  7. Competing software
  8. Similarities with other domains

Problem and scope

A problem may be a difficulty experienced by users/customers or an opportunity that can create benefit such as productivity or sales improvement. A strong problem statement is short and precise. Scope is narrowed by first imagining what the system could do, then deliberately excluding lower-priority capabilities until the first release is manageable. If the scope becomes too narrow, revisit the high-level goals.

Stakeholders

Stakeholders include people and organizations affected by the outcome: the customer who commissions the system, developers who build it, direct and indirect users, and other parties whose work or interests are influenced by the system.

Lab activities

Activity 1 · Understand the domain
For the assigned system, identify as many useful information sources as possible; identify relevant stakeholders; then write a short domain analysis containing only the information a software engineer truly needs.
Activity 2 · Define the solution boundary
List a broad set of possible system capabilities, narrow them to a minimal high-value first release, and write a precise problem statement connected to high-level goals.

Share and discuss the result with the class so the problem framing can be improved before requirements are developed.
