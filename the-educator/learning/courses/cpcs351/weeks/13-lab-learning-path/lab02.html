Lab 02 · Process Thinking

Software Development Models

Learn to select a development process from project evidence rather than from habit. Compare iterative and sprint-based development, reason about uncertainty and change, and start shaping the term project.

Process models in practice

A software development process or SDLC structures the work needed to create, evolve and maintain a software product. A process model describes how activities such as analysis, design, coding and testing are organized and repeated.

Iterative development

Build the product in small increments. Each iteration includes a development cycle—analysis, design, coding and testing—and ends with a review whose results influence later iterations. The key advantage is early working software and earlier feedback.

Scrum and sprints

A sprint is Scrum’s basic development timebox. It has a sprint goal, produces a demonstrable slice of value, and includes design, coding, testing, debugging and optimization. Repeated sprints allow uncertainty and risk to be addressed progressively.

Horizontal vs vertical prototypes

The lab asks students to distinguish prototypes that explore a broad interface or surface of the system from prototypes that implement a narrow feature through deeper layers. Use the distinction to explain what question the prototype is intended to answer.

Activity 1 · Select and justify

For each scenario, choose a suitable process model and provide two reasons based on the evidence in the scenario:

  1. A complex, long-running mobile application using Java and Oracle.
  2. A system whose customers are unsure what they want and whose requirements are poorly defined.
  3. A fairly large project in a familiar domain where an experienced team expects limited variation from previous systems.
  4. A complex, long-running Java/Oracle project with moderate-to-high risk of changing requirements.
Discussion: identify two ways Scrum can address problems commonly associated with a waterfall process.

Activity 2 · Start the term project

  1. Form a group of 2–4 students.
  2. Brainstorm three suitable project titles.
  3. Present the candidates to the class.
  4. Select one project.
  5. Draft a rough project definition.
  6. Present the definition for instructor/class feedback.
