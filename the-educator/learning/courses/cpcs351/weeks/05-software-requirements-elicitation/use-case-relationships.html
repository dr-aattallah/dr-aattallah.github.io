Use-Case Relationships

A relationship is meaningful only if it explains participation, mandatory reuse, optional extension, or specialization.

5of 9 pages
Core lecture content Clarification & study aids
Learning focus

Choose association, «include», «extend», or generalization based on the actual semantics of a scenario and draw the arrow in the correct direction.

Four relationship meanings

Do not memorize arrows without the logic

🔗 Association

Actor ───── Use Case

Actor and use case communicate or participate with one another.

♻️ «include»

Base - - -▷ Included

Required reused behavior. The base use case depends on the included behavior to complete.

➕ «extend»

Extension - - -▷ Base

Optional/conditional behavior is inserted into a base use case that is already meaningful by itself.

🌳 Generalization

Specific ─────▷ General

A specialized actor or use case inherits the meaning/behavior of a more general parent.

Official lecture examples

Required vs. optional is the key distinction

«include» · ATM

Withdraw Cash and Transfer Cash can include Verify Balance. The reused behavior is necessary to complete the base behavior.

«extend» · Purchase

Print Receipt can extend Purchase Book with Credit Card when the customer requests a receipt. The purchase is still meaningful without the optional extension.

Worked example · ATM actors

One system, several external roles

Customer: Withdraw Cash, Deposit Funds, Check Balance, Transfer Funds. Maintenance: Perform Routine Maintenance. Stocker: Fill ATM with Cash. Bank: external supporting system involved in transaction completion.

Decision test

Which relationship should I choose?

Does an actor interact with the goal?

Use association.

Must common behavior always execute?

Use «include».

Is extra behavior optional or conditional?

Use «extend».

Is one actor/use case a specialized form of another?

Use generalization.

External notation reference: uml-diagrams.org Use Case Reference. Its examples reinforce that «include» is required behavior, «extend» is optional/conditional behavior, and generalization is specialization.
Memory hook

Include = MUST. Extend = MAY. Generalization = IS-A. Association = INTERACTS.

Common trap

Do not use «extend» to mean “happens later”

«extend» does not mean chronological sequence. It means optional or conditional behavior inserted into a base use case. If two steps always occur in sequence, that alone is not a reason to connect their use cases with «extend».
