Use-Case Relationships

A relationship is useful only when it explains participation, mandatory reuse, optional extension, or specialization.

6of 9 pages
Learning focus

Choose association, «include», «extend», or generalization from scenario semantics and draw the direction correctly.

Four meanings

Learn the logic before the arrow

🔗 Association

Actor ─── Use Case

Actor participates in the use case.

♻️ «include»

Base - -▷ Included

Required reused behavior needed to complete the base use case.

➕ «extend»

Extension - -▷ Base

Optional/conditional behavior added to a base use case that is meaningful by itself.

🌳 Generalization

Specific ───▷ General

A specialized actor or use case inherits from a more general parent.

Official examples

Required vs. optional is the crucial distinction

«include» · ATM

Withdraw Cash and Transfer Cash can include Verify Balance because the reused behavior is necessary.

«extend» · Purchase

Print Receipt can extend Purchase Book with Credit Card when a receipt is requested.

Decision test

Which relationship fits?

Actor interacts with goal?

Association

Common behavior must execute?

«include»

Extra behavior is optional?

«extend»

One element specializes another?

Generalization

Memory hook

Include = MUST. Extend = MAY. Generalization = IS-A. Association = INTERACTS. «extend» does not mean “happens later.”
