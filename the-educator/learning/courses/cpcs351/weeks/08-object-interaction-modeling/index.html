Topic 08 · Chapter 9

Object Interaction Modeling

Turn a use-case request into a precise story of how software objects collaborate behind the interface.

1of 14
Learning destination

Identify background processing, write scenarios and scenario tables, translate them into sequence diagrams, distinguish analysis from design, and connect messages to responsibilities and implementation.

The big idea

What happens after the actor clicks?

👤 Actor request
→
🖥️ Foreground UI
→
⚙️ Object collaboration
→
✅ System response

Actor-system interaction models the visible foreground. Object Interaction Modeling (OIM) specifies how objects interact to perform the background processing of a business process.

Learning path

One transformation, step by step

🔎1 · Find the work

Locate nontrivial use-case steps that require processing beyond presentation.

🧾2 · Tell the scenario

Describe subject, action, object acted upon, and required data.

📋3 · Structure it

Organize the interaction in a scenario table.

⏱️4 · Visualize time

Translate the scenario into a sequence diagram.

🧠5 · Design responsibilities

Use messages to expose responsibilities and methods.

🔍6 · Review semantics

Check ordering, nesting, calls, guards, loops and creation.

Running example

Library Checkout will grow with you

Instead of isolated fragments, this topic repeatedly returns to the lecture’s Library Checkout case: Patron submits call numbers → GUI delegates → controller coordinates → DBMgr retrieves/saves → Loan is created → Document availability changes → result returns. Each later lesson adds one modeling layer.

Mental model

Use-case step → scenario → scenario table → sequence diagram → responsibility → method.
