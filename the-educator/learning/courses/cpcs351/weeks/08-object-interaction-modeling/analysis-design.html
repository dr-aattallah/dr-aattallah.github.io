Analysis vs Design Sequence Diagrams

Similar notation can answer two very different questions.

🔎 Analysis

  • Application problem-oriented
  • Models the application domain
  • Describes what the world is
  • Project-oriented decisions
  • Should allow design alternatives

🛠️ Design

  • Software solution-oriented
  • Models the software system
  • Prescribes a software solution
  • System-oriented decisions
  • Usually reduces implementation choices

Lecture contrast: library system

Manual analysis: Librarian receives ID card
→
Librarian finds patron folder
⇢
Software design: GUI → Controller → DBMgr

An analysis sequence diagram can model an existing manual operation with little design decision. A design sequence diagram introduces software objects and assigns solution responsibilities.

Exam trap

Do not call a diagram “design” merely because it uses UML. Ask whether its participants represent the problem world or a chosen software solution.
