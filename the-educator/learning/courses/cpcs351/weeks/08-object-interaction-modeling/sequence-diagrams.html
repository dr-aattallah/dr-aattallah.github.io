UML Sequence Diagram notation — source visual

The reference defines a sequence diagram as an interaction diagram focused on message exchange between lifelines. The figure below is the actual notation overview published by uml-diagrams.org, not a recreated diagram.

Lifeline

A named participant. Its head identifies the participant and the vertical line represents its lifetime during the interaction.

Execution specification

The thin rectangle on a lifeline represents a period in which the participant executes behavior, sends a signal, or waits for a reply.

Synchronous message

A call message where control passes to the receiver; the caller normally waits for completion.

Asynchronous message

A message that allows the sender to continue without waiting for the receiver to finish.

Return message

A dashed reply used when showing the returned result improves the explanation.

Creation message

Creates a participant; the new lifeline begins at the point where the creation message arrives.

Destruction occurrence

The X terminates a lifeline. No later occurrence may appear below it.

Gate

A message connection point on the interaction frame used to connect communication across an interaction boundary.

Duration constraint

Constrains elapsed time between occurrences; the source overview illustrates it beside the lifeline.

Interaction use · ref

References another interaction so complex behavior can be reused instead of redrawn.

The four translation cases

1 · Actor → Object

Actor sends input/action to the object acted upon.

2 · Object → Actor

Object communicates a message/result to the actor.

3 · Object → Object

One software object invokes another.

4 · Self-call

Subject and object acted upon are the same object.

How to read any sequence diagram

Start at the top, identify every lifeline, then move downward one message at a time: sender → message → receiver → resulting execution or reply. Never read it left-to-right as if it were a flowchart.
