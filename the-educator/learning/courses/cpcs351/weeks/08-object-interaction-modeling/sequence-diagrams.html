UML Sequence Diagram notation — source visual

The reference defines a sequence diagram as an interaction diagram focused on message exchange between lifelines. The figure below is the actual notation overview published by uml-diagrams.org.

Study priority: master the Core notation first. Advanced/reference symbols are useful for reading richer diagrams, but they should not distract you from the central skill: translating a scenario into correctly ordered interactions.

Reading rule: participants are arranged horizontally, time moves downward, arrows show communication, activation bars show execution, and frames/guards explain control logic.

The four translation cases

1 · Actor → Object

Actor sends input/action to the object acted upon.

2 · Object → Actor

Object communicates a message/result to the actor.

3 · Object → Object

One software object invokes another.

4 · Self-call

Subject and object acted upon are the same object.

How to read any sequence diagram

Start at the top, identify every lifeline, then move downward one message at a time: sender → message → receiver → resulting execution or reply. Never read it left-to-right as if it were a flowchart.
