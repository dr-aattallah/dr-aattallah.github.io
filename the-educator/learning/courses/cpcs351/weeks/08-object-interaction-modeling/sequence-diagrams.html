Scenario Table → UML Sequence Diagram

Translate a scenario into the official UML interaction notation. Time runs downward; messages show who communicates with whom and in what order.

First: learn the real UML notation

A sequence diagram is a UML interaction diagram centered on message exchange between lifelines. Before drawing one, learn to recognize the standard visual vocabulary.

Lifeline

A participant in the interaction. Its dashed vertical line represents its existence as time moves downward.

Execution specification

The thin rectangle on a lifeline shows a period in which that participant is executing behavior or waiting for a reply.

Synchronous message

A call where the sender transfers control and normally waits for completion or a reply.

Asynchronous message

A message whose sender does not wait for the receiver to finish before continuing.

Return message

Usually drawn dashed; it can make the returned result explicit when that improves understanding.

Creation / destruction

A creation message starts a new lifeline; an X marks a destruction occurrence after which no further occurrence may appear.

Gate

A connection point relating a message outside an interaction fragment to a message inside it.

Interaction use (ref)

References another interaction so a large sequence diagram can reuse behavior without redrawing it.

The four translation cases

1 · Actor → Object

Actor sends input/action to the object acted upon.

2 · Object → Actor

Object communicates a message/result to the actor.

3 · Object → Object

One software object invokes another.

4 · Self-call

Subject and object acted upon are the same object.

How to read any sequence diagram

Start at the top, identify every lifeline, then move downward one message at a time: sender → message → receiver → resulting execution or reply. Never read it left-to-right as if it were a flowchart.
