Library Checkout: From Request to Object Story

This is the backbone example for the rest of Topic 08.

Trigger

Expanded use-case step

The patron enters the call numbers of documents to be checked out and clicks Submit.

Normal interaction scenario

4.1
Checkout GUI asks Checkout Controller to check out the documents using their call numbers.
4.2
Checkout Controller creates a blank result message.
4.3
For each call number, the controller asks DBMgr for the Document.
4.3.3
If the document exists, the controller checks whether it is available.
4.3.3.2
If available, create Loan(p,d), set Document unavailable, save Loan and Document, and record success.
4.4
Checkout Controller returns msg to Checkout GUI.
4.5
Checkout GUI displays msg to Patron.

Alternative outcomes already visible

Document available

Create Loan, change availability, persist objects.

Document unavailable

Write “document not available” to msg.

Document not found

Write “document not found” to msg.

Do not draw yet
