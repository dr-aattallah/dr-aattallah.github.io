Translation rules

What UML constructs become in code

➡️ Message → method call

The receiver normally owns the invoked operation.

🔁 loop → iteration

loop [for each cn] becomes a loop over cnList.

🛡️ guard → condition

[u != null] and [available] become conditions.

✨ create → constructor

«create» Loan(u,d) becomes new Loan(u,d).

🔄 state message → behavior

setAvailable(false) asks Document to change its own state.

💾 persistence → DB responsibility

Save/retrieve messages become persistence operations.

Implementation

One coherent Java realization

Boundary: CheckoutGUI

public class CheckoutGUI {
    private final CheckoutController controller;

    public CheckoutGUI(CheckoutController controller) {
        this.controller = controller;
    }

    public String checkout(String uid, String[] cnList) {
        // capture input, delegate background work,
        // then display/return the result
        return controller.process(uid, cnList);
    }
}

Control: CheckoutController

public class CheckoutController {
    private final DBMgr dbm;

    public CheckoutController(DBMgr dbm) {
        this.dbm = dbm;
    }

    public String process(String uid, String[] cnList) {
        User u = dbm.getUser(uid);
        if (u == null) return "Unknown user";

        for (String cn : cnList) {
            Document d = dbm.getDocument(cn);
            if (d != null && d.isAvailable()) {
                Loan l = new Loan(u, d);
                dbm.saveLoan(l);
                d.setAvailable(false);
                dbm.saveDocument(d);
            }
        }
        return "Checkout completed";
    }
}

Persistence collaborator: DBMgr

public class DBMgr {
    public User getUser(String uid) { /* retrieve */ }
    public Document getDocument(String cn) { /* retrieve */ }
    public void saveLoan(Loan loan) { /* persist */ }
    public void saveDocument(Document d) { /* persist */ }
}
Architecture lesson: the sequence diagram does not force one Java architecture, but it should remain internally coherent. Here the GUI is a boundary, the controller coordinates the use case, domain objects own domain behavior, and DBMgr owns persistence operations.
