Fork, Join, Concurrency & Object Flow

Model work that can proceed in parallel, the point where it must synchronize, and the information moving through the process.

8of 13 pages
Core lecture

Parallel work

  • A fork splits one flow into concurrent threads.
  • A join synchronizes concurrent threads before continuing.
  • Fork/join means parallel obligations; decision/merge means alternatives.
  • An object node such as :NewOrder or :Invoice can show object flow between actions.

Design judgment

Do not invent concurrency

Use a fork only when activities are logically independent enough to proceed concurrently. Drawing parallel branches merely to make a diagram look sophisticated creates false system requirements.

Exam cue

Decision = one path. Fork = multiple paths. Merge = alternatives reunite. Join = parallel work synchronizes.
