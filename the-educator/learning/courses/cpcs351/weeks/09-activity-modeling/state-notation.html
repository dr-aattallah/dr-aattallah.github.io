States, Events, Transitions & Guards

The minimum vocabulary needed to read and construct a UML state machine correctly.

3of 12 pages
Learning focus

Distinguish state, event, transition, guard, start, and final state—and label them meaningfully.

Core notation

States

  • At a given point in time, the modeled object is in a state and remains there until a transition occurs.
  • A state is shown as a rounded rectangle.
  • Useful state names often describe an ongoing condition: Waiting, Dialing, Powered.
  • A filled black circle is the initial node; a bullseye-style node is the final node.
Core notation

Transitions and guards

A transition is an instantaneous change of state in response to an event. A guard is a Boolean condition that must be true for that transition to occur.

Available
reserve [memberValid]
Reserved

Read it as: while the Book is Available, event reserve moves it to Reserved only if memberValid is true.

Time events

Behavior can be time-triggered

Transitions may be triggered by elapsed time, such as after(30s). Traffic lights are a natural example: Green → Yellow → Red as timers expire, while sensor events and guards can create alternative behavior.

Common mistake

A guard is not a state. “Payment approved” may be a condition guarding a transition; “Paid” may be a state if the object remains in that condition over time.

Mini check

Event or state?

submitted usually describes an event; Under Review describes a persistent state. Ask whether it happens or whether the object can remain there.
