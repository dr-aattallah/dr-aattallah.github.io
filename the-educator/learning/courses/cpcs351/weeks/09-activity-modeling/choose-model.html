State vs Activity vs Sequence

The skill is not drawing more UML. The skill is choosing the smallest model that answers the behavioral question.

One scenario, three lenses

Online order

  • Sequence: Customer → OrderController → PaymentService → Inventory.
  • State: Order moves New → Paid → Packed → Shipped → Delivered/Cancelled.
  • Activity: verify payment and stock, perform parallel preparation, pack, ship, and close the order.

These models are complementary. They should not be forced to duplicate each other.

Modeling challenge

Diagnose the requirement

“A support ticket may be Open, Assigned, Waiting for Customer, Resolved, or Closed.” → State. “After submission, validate data, run fraud screening and credit checks in parallel, then decide.” → Activity. “Show the calls among UI, controller, repository, and notification service.” → Sequence.

Strong answer pattern

Name the model, then justify it using the behavioral question—not merely the notation it contains.
