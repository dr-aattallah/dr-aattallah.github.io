Software Security

Security Bugs & Programming Assumptions

5of 7 pages

Where software-security bugs come from

The lecture identifies invalid programming assumptions as a common reason for security bugs—assumptions attackers may deliberately look for.

Input & memory

Weak input checking, buffer overflow and integer overflow.

Timing & environment

Race conditions (Time of Check / Time of Use) and programs running in new environments.

Configuration & privilege

Log files containing sensitive information, configuration bugs, unnecessary privileges, monoculture and security bypass.

Story checkpoint

The programmer assumed “users will enter normal input.”

Attackers do not have to respect that assumption. The lecture frames many software-security bugs as invalid programming assumptions: assumptions that may work during ordinary use but create exploitable weaknesses.

ASSUMPTION: input is always valid
→ weak input checking
ASSUMPTION: values fit expected ranges
→ integer / buffer overflow
ASSUMPTION: checked state will not change before use
→ race condition (TOC/TOU)
ASSUMPTION: logs are harmless
→ sensitive information in log files
