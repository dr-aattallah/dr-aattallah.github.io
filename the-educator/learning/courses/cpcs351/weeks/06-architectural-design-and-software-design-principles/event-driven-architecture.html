Event-Driven & Transformational Architectures

Two very different behaviors need two very different organizing structures: react to events versus transform input into output.

6of 10 pages
1
Architecture A · Reactive systems

⚡ Event-Driven Architecture (EDA)

React to events: independent components respond when something happens.

How it works

  • An event records something that happened.
  • Producers publish events to a broker or event bus.
  • Subscribed consumers react independently, often asynchronously.
  • Event handling can depend on current system state.

When to use it

  • Real-time notifications and activity feeds
  • Multiple independent services
  • IoT telemetry and scalable cloud applications
  • Workloads that benefit from loose coupling
REAL-WORLD EXAMPLE · E-COMMERCE

Customer places an online order

🛒Customer checkoutOrder placedPublish OrderCreated
→
🔀Event brokerDistributes OrderCreated to subscribers
→
📧NotificationSend confirmation
📦InventoryUpdate or reserve stock
💳PaymentInitiate payment workflow

Illustrative event flow: the three consumers subscribe to the same event and can process it independently. Payment success should be confirmed by a separate payment-result event.

✓ Result: Independent consumers, extensible features, asynchronous processing and improved scalability.
2
Architecture B · Controlled processing

⚙️ Transformational Architecture

Transform input into output: a main program coordinates specialized processing steps.

How it works

  • A main program controls the processing sequence.
  • Subroutines handle specialized transformations.
  • Inputs are validated, processed and converted to outputs.
  • Steps may include branches or parallel computation.

When to use it

  • Grade calculation and reporting
  • Batch imports, exports and ETL pipelines
  • Scientific and numerical computation
  • Defined input-to-output workflows
REAL-WORLD EXAMPLE · UNIVERSITY GRADES

Student grade processing system

The main program invokes reusable subroutines in a controlled sequence.

📄InputGrades CSV / Excel
→
📥Read dataParse student records
→
🛡️ValidateCheck rules and constraints
→
🧮CalculateGrades, GPA, statistics
→
📊GenerateReports and dashboards

✓ Result: Predictable processing, reusable subroutines, clear responsibilities and testable output.

Compare the behaviors

Reactive events vs controlled transformation

Dimension⚡ Event-driven⚙️ Transformational
StimulusExternal event, message or actionInput dataset or processing request
Execution orderEvent arrival is unpredictable; consumers may run independentlyMain program coordinates a defined processing flow
StateMay determine how an event is handledUsually not the central architectural idea
ComponentsEvent producers, broker and consumersMain program and specialized subroutines
InteractionPublish/subscribe and event handlingFunction or service calls
ExamplesOrder events, notifications, IoT, live analyticsGrade reports, data pipelines, scientific computation

Key takeaways

Choose architecture by behavior

⚡ Event-driven = REACT

What should happen when event X occurs, possibly in state Y?

⚙️ Transformational = PROCESS

What sequence converts the given input into the required output?

Modern applications can combine both. Select architectural styles based on requirements and behavior—not personal preference.
