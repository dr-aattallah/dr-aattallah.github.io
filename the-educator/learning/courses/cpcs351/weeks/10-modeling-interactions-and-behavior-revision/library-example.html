One Library System, Four Views

The same domain can be modeled differently depending on the question being asked.

2of 6 pages

Use case view — user goals

The revision example identifies a Borrower who can reserve a book, borrow a copy, and return a copy, while a Librarian updates the catalogue. The emphasis is actors and tasks.

Class view — static structure

The example connects LibraryMember, Copy, and Book, and specializes LibraryMember into Student and Staff. This view answers what classes exist and how they are related.

Sequence view — dynamic collaboration

A LibraryMember sends borrow(theCopy); the collaboration checks okToBorrow, sends borrow to the copy, and records borrowed at the book. The emphasis is message order used to fulfil a task.

State view — one object's lifetime

A Book can be Borrowable or Not borrowable. Events such as borrowed() and returned(), with conditions such as [last copy] or [not last copy], cause or preserve state transitions.

Added study aid

Exam lens

If a scenario mentions actors and goals, think use case. If it lists entities and multiplicities, think class. If it describes calls/messages, think sequence. If it follows one object's changing condition, think state.
