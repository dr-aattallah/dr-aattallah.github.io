Verification and Validation

The two questions are different: are we building the product right, and are we building the right product?

2of 8 pages
Core lecture content Clarification & study aids
Learning focus

Define software quality and explain the role of quality-assurance activities in the software process.

Core lecture

What you need to understand

  • Verification checks whether an implementation or lower-level artifact conforms to its specification.
  • Validation checks whether the model or system corresponds to real customer needs and the real world.
  • Static techniques include reviews, inspections, walkthroughs, and peer reviews; dynamic techniques execute software through testing.
  • V&V activities appear throughout the life cycle, not only after implementation.
Visual model

See the idea

Verification → specification conformity
Validation → customer/real-world fitness
Worked example

Password-reset feature

Verification: implementation matches the approved reset rules. Validation: the reset flow actually solves users’ access problem safely and understandably.

Remember

Verification asks “right way?”; validation asks “right product?”.
