Software Quality Attributes

A software system can be excellent in one dimension and weak in another. Five important quality attributes are usability, efficiency, reliability, maintainability, and reusability.

“Do not ask only ‘Is this good software?’ Ask: good for whom, good in what way, and good for how long?”

Visual Hook

Five views of the same software

The same application looks different depending on who—or what—is observing it.

ONE SOFTWARE
SYSTEMFive different quality questions

Usability

The Machine Sees

Efficiency

Does it avoid wasting CPU time, memory, and other resources?

Operations Sees

Reliability

Does it do what it is required to do without failing?

The Engineer Sees

Maintainability

Can it be changed easily when needs evolve?

The Next Project Sees

Reusability

Can useful parts be used elsewhere without reprogramming them?

One system can look very different depending on which quality dimension we examine.
Five Quality Dimensions

The five attributes, preserved

Usability
Users can learn it fast and get their job done easily.
Efficiency
It does not waste resources such as CPU time and memory.
Reliability
It does what it is required to do without failing.
Maintainability
It can be easily changed.
Reusability
Its parts can be used in other projects, so reprogramming is not needed.
Example · Mobile Banking

The User Experience Lab

Several quality attributes can appear simultaneously in the same system.

Mobile Bank
Usability

A transfer can be completed with clear steps and understandable feedback.

Efficiency

The app responds quickly and does not consume excessive battery, CPU, or memory.

Reliability

The transfer either completes correctly or reports failure safely—without silently losing the transaction.

Reliability as a Timeline

“Works once” is not reliability

Reliability means doing what is required without failing across repeated use and time.

Engineering Trade-offs

Quality attributes can compete

Improving one quality attribute can sometimes make another harder or more expensive to achieve.

Usability
clearer interaction
Efficiency
resource discipline
Reliability
strong protection
Maintainability
easy evolution
Reusability
generalized components

Example: generalizing a component for reuse can introduce abstraction and complexity. Heavy reliability mechanisms can consume additional resources. Engineering is about choosing an appropriate balance for the system's context.

Mentor Insight

There is no single “quality switch.” A system can be usable but inefficient, reliable but difficult to maintain, or reusable but unnecessarily complex. Quality has dimensions.

Key Takeaway

The original lecture identifies five quality attributes: Usability, Efficiency, Reliability, Maintainability, and Reusability. Together they remind us that software quality is multidimensional rather than one final score.

Think Like a Software Engineer

A system is extremely fast and never crashes—but users cannot figure out how to complete their tasks. Is it high-quality software?

Which attribute is strong? Which one is weak? Can one excellent attribute compensate for another that prevents users from succeeding?
