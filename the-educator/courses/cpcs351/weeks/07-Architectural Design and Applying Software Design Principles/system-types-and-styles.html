Topic 07 · Lesson 05

System Types → Architectural Styles

Match the dominant behavior of the system to a reusable architectural structure.

5of 14
Learning focus

Learn the source mapping and understand that style selection follows system classification.

Core lecture

Source mapping

→Interactive SystemN-Tier
→Event-Driven SystemEvent-Driven
→Transformational SystemMain Program & Subroutines
→Object-Persistence SubsystemPersistence Framework
→Client-server SystemClient-Server
→Distributed, DecentralizedPeer-to-Peer
→Heuristic Problem-SolvingBlackboard

How the decision is made

  • Determine design objectives and system type first.
  • Consult an architectural-styles repository for a suitable style.
  • If a style is available, adapt it to the application.
  • If no complete style fits, use useful partial designs and perform custom architectural design.
Remember

Architectural styles are reusable solution structures, not rigid templates.
