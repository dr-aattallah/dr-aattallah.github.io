Event-Driven Architecture

Let events trigger behavior while a state-based controller determines what each event means now.

7of 14
Learning focus

Connect event-driven system characteristics to an event-driven architectural structure.

  • The source diagram places a State-Based Controller at the center of several components.
  • Components send events and receive instructions.
  • Events do not need to arrive in a fixed sequence.
  • The same event may lead to different behavior depending on the current state.
  • Multiple external entities can be active at once.
  • Timing and temporal constraints can be part of correctness.
