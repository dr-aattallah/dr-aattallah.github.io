Architectural Design Process & Objectives

Choose an architecture by starting with objectives, system type, and quality concerns.

3of 14
Learning focus

Follow the architectural decision process and evaluate maintainability, COTS use, performance, reliability, security, fault tolerance, and recovery.

Core lecture

Decision process

  • Determine design objectives from requirements; examples include fault tolerance, safety, security, and maximum performance.
  • Determine the type of system or subsystem.
  • Apply an existing architectural style when suitable; otherwise perform custom architectural design.
  • Specify subsystem functions, interfaces, and interaction behavior.
  • Review the architecture and iterate when objectives or principles are not satisfied.
  • Consider ease of change and maintenance.
  • Consider use of commercial off-the-shelf (COTS) parts.
  • Performance: real-time data processing or huge transaction volumes?
  • Reliability: must intended functions be performed correctly under assumed conditions?
  • Security: how much protection is required for data and program resources?
  • Software fault tolerance: how much operation must continue after a software problem?
  • Recovery: how well must the system return to a previous state after a crash?
