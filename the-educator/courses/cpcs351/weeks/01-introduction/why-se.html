Topic 01 · Section 3

Why Software Engineering?

Software has become the engine of modern life. Systems are larger, more complex, more connected, and more important than ever. That is why building serious software requires a disciplined engineering approach.

“Great software does not happen by accident. It is engineered.”
— Your Software Engineering Mentor

The Story

From a small program to a real software system

The need for software engineering becomes easier to understand when we look at what happens as software grows.

01
💻

It starts simple

One developer writes a small program. The program is short, the requirements are simple, and one person understands most of it.

02
🧩

Then it grows

New features appear. Databases, APIs, security, mobile applications, cloud services, and integrations are added.

03
🕸️

Complexity explodes

Components depend on each other. A small change can unexpectedly affect many other parts of the system.

04
👥

Many people must work together

Developers, analysts, testers, designers, operations teams, managers, and stakeholders must coordinate their work.

05
🛠️

Engineering becomes necessary

Processes, methods, modeling, tools, testing, and quality practices help the team build the right system in the right way.

From the Original Lecture

Why do we need Software Engineering?

🌍

Software is everywhere

Companies and organizations depend on software to operate, compete, communicate, and provide services. Today software is central to finance, healthcare, education, transportation, government, entertainment, and many other sectors.

📈

Systems are growing and becoming more complex

Real systems may contain millions of lines of code and large numbers of interacting components, services, databases, devices, and external systems.

💰

Software represents major investment

The original lecture emphasizes how software became a major portion of overall system cost. The exact percentages in the original slide are historical examples, but the engineering lesson remains: software requires substantial development and maintenance effort.

🛡️

Quality can be critical

In embedded and safety-critical systems, failure may be expensive, dangerous, or unacceptable. Examples include medical devices, vehicles, aviation systems, industrial control systems, and critical infrastructure.

Historical Example from the Original Lecture

Large systems cannot be built by one person

The original lecture uses lines of code and programmer productivity estimates to illustrate the scale problem. These figures should be understood as teaching examples from the original material, not as modern productivity benchmarks.

Original lecture example
50–100 lines of source code per day for a typical software engineer in the lecture example.
10,000 LOC A small system would require approximately 100–200 engineer-days.
500,000 LOC A medium system would require thousands of engineer-days for one person.
Many Engineers Real-world systems therefore require teams working together.

Modern Context

Today's systems are complex in more ways than code size

Lines of code alone do not measure software complexity. Modern systems may combine:

Cloud infrastructure APIs Microservices Databases Mobile applications Security controls AI components Third-party services Continuous deployment Millions of users

Implication

What happens without disciplined engineering?

⏱ Delays 💸 Budget overruns ⚠ Low quality 🔐 Security problems 🧱 Difficult maintenance 😕 Unhappy users
Think Like a Software Engineer

Look around you. Which software systems do people rely on every day?

Choose one system—for example online banking, a hospital system, airline booking, university registration, or navigation. What could happen if that software failed? Your answer should help explain why software engineering matters.
