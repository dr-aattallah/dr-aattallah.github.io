Object-Oriented Software Engineering

Object-oriented software engineering is a specialization of software engineering. It views the world and systems as collections of objects that relate to and interact with one another.

“Instead of seeing one huge program, see a world of collaborating objects.”
— Your Software Engineering Mentor

From the Original Lecture

The object-oriented view

The lecture defines Object-Oriented Software Engineering (OOSE) as a specialization of software engineering. The object-oriented paradigm views the world and systems as consisting of objects that relate and interact with each other.

Visual Hook

The Object Universe

Imagine a software system not as one giant block, but as a small universe of objects. Each object has a role, information it owns, and interactions with other objects.

Student Requests registration, views schedule, receives feedback.
Course Knows code, capacity, prerequisites, and course information.
Registration Coordinates enrollment rules, conflicts, and status.

OOSE Includes

The four elements named in the lecture

↻

OO Processes

Development processes organized around object-oriented analysis, design, implementation, and evolution.

🧭

OO Methodologies

Structured approaches that guide engineers in identifying, modeling, assigning responsibilities, and designing objects.

◇

OO Modeling Languages

Visual languages such as UML help describe classes, objects, relationships, interactions, and behavior.

🛠

OO Tools

Tools support modeling, coding, testing, refactoring, documentation, collaboration, and other engineering tasks.

Mental Model

From real-world concepts to software objects

Real-world concept A student has an ID, name, program, and academic record.
→
Software representation A Student object can hold state and participate in operations such as registration.
Real-world concept A course has capacity, prerequisites, schedule, and instructor information.
→
Software representation A Course object represents this data and participates in rules and interactions.
Real-world interaction A student attempts to enroll in a course.
→
Object interaction Objects collaborate to check prerequisites, capacity, schedule conflicts, and create enrollment.

Visual Story

Thinking in objects

1. Identify concepts

Look at the problem domain and identify meaningful entities, roles, events, and responsibilities.

2. Model relationships

Understand how these concepts relate, what information they own, and what responsibilities belong where.

3. Design collaborations

Define how objects communicate and cooperate to realize system behavior.

Mentor Insight

Object orientation is not merely using classes in a programming language. In software engineering, it is a way of analyzing, modeling, designing, and structuring systems around objects and their collaborations.

Key Takeaway

OOSE specializes software engineering around the object-oriented paradigm: systems are viewed as interacting objects, supported by OO processes, methodologies, modeling languages, and tools.

Think Like a Software Engineer

What objects would exist in an online food-delivery system?

Identify at least five candidate objects. Then choose two and describe one interaction between them. Do not think about database tables yet—think about domain concepts and responsibilities.
