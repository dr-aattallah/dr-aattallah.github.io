Software Testing

Evaluate software against requirements, expose errors and undesired behavior, and design focused tests that reveal failures efficiently.

CLO 17

Describe and distinguish among the different types and levels of testing: unit, integration, system, and acceptance.

Core lecture

What testing means

Testing evaluates a system or its components to determine whether specified requirements are satisfied. It executes software to identify gaps, errors, missing requirements, and behavior that differs from what is desired.

Two purposes

Demonstrate satisfaction
Show that functional and non-functional requirements are met.
Detect problems
Find semantic, logical and computation errors, plus undesired behavior that may compromise effectiveness or security.

Questions testing helps answer

  • Does it work as expected and meet user requirements?
  • Is it what users expect, and do they like it?
  • Is it compatible with other systems?
  • How does it perform and scale as users increase?
  • Which areas need more work, and is it ready for release?
Testing is evidence

A passed test gives evidence about a particular requirement and input situation; it does not prove that no defects remain.
