CPCS 351 / Topic 06 / Find Candidates
Read for domain action

Verb–noun phrases reveal candidate goals.

Search the requirements specification for domain-specific “do something” phrases. Treat them as candidates—not final use cases—then connect each phrase to an actor and a system boundary.

Highlight language that describes business outcomes. Technical verbs often describe implementation steps, not actor goals.

Extraction pattern

Move from sentence to candidate model element

The library system must allow a patron to check out documents.
→

Candidate use caseCheck Out Document
Second extraction

Do not lose the subject

The advising system must allow an advisor to publish available appointment slots.
→
ActorAdvisor
+
Subject / candidateAdvising System · Publish Availability
Candidate screening

Some verb–noun phrases are too small or too technical

Press Submit ButtonUser-interface action; ask which complete goal the submission advances.
Search Linked ListComputer-science operation, not a domain business process.
Query DatabaseImplementation mechanism; ask what information the actor is trying to obtain.
Process DataToo vague to communicate actor value or a domain outcome.
Start SystemMay be a legitimate administrative goal only if an external operator needs and acknowledges the outcome.
Naming

Use concise domain verb + noun names

Check Out Document

Concrete library-domain task and outcome.

Search Programs

Goal-centered and meaningful to a study-abroad user.

Withdraw Cash

Complete ATM customer task—not “Dispense Notes.”

Mentor insight

Extraction is only the first pass. One requirement may suggest several use cases, and several requirements may be satisfied by one coherent use case.

Key takeaway

Highlight domain-specific verb–noun phrases, identify the responsible actor and subject, and reject phrases that describe isolated UI actions or internal computation.
