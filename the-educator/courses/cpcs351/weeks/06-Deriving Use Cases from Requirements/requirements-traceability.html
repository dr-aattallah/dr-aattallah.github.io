CPCS 351 / Topic 06 / Traceability
Coverage with evidence

Traceability shows why each use case exists.

A Requirements–Use Case Traceability Matrix maps requirements to the use cases that satisfy them. It reveals missing coverage, unnecessary behavior, change impact, and priority.

A diagram can look complete while silently missing a requirement. Traceability converts that impression into an auditable coverage claim.

Questions the matrix answers

Coverage, necessity, and priority

Coverage

Which use cases satisfy each required capability? Are any requirements unmapped?

Necessity

Does every use case trace to a stakeholder requirement, business rule, or justified supporting need?

Priority & impact

Which use cases satisfy the most important requirements, and what changes if a requirement moves?

Read both directions

Rows and columns expose different defects

Empty requirement row

A required capability has no use case coverage. A use case may be missing, or the requirement may need clarification.

Empty use case column

The use case has no stated justification. It may be unnecessary, derived from an undocumented rule, or supporting behavior that needs explanation.

Weighted priority

Use importance to guide planning—not to replace judgment

The lecture demonstrates requirement weights and use-case scores. A simple score can show which use cases cover high-priority requirements, but dependencies, risk, architecture, cost, and learning value also affect release order.

Classroom heuristic: Use-case score = sum of the priority weights of requirements traced to that use case. Treat the score as a planning aid, not universal scientific law.
Think like a software engineer

One high-priority requirement maps to no use case. What should the team do?

Do not immediately invent a use case. Revisit the requirement, actors, boundary, and candidate goals; the behavior may be missing, non-functional, or satisfied across several existing use cases.

Key takeaway

Traceability demonstrates coverage and justification, highlights gaps and extra scope, supports change analysis, and informs—but does not mechanically decide—priority.
