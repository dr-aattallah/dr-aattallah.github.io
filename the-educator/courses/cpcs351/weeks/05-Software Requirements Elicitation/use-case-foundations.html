UML communication model

Show who needs what from the system.

A use case model captures user goals, interactions with the system, and the behavior required to achieve valuable results. A use case diagram presents a useful subset of that model graphically.

A use case diagram is a map of goals and external roles—not a flowchart, screen design, database model, or complete specification.

Subject

The system or subsystem under consideration, shown as a named boundary.

Actor

An external role—human, system, organization, or device—that interacts with the subject.

Use case

A complete and useful capability that produces an observable result for an actor.

Association

A communication relationship between an actor and a use case.

Mentor insight

Actors represent roles, not named individuals. One person may play several roles, and a non-human system can also be an actor when it is external to the chosen boundary.

Key takeaway

A use case diagram communicates a named system boundary, external actors, valuable user-goal use cases, and the relationships connecting them.
