CPCS 351 / Topic 05 / Use Case Relationships
Relationship semantics

Use relationships only when they clarify meaning.

Association, «include», «extend», and generalization answer different questions. Arrow direction alone is not enough—you must understand the dependency being expressed.

The most common mistake is adding relationships because the diagram looks “more UML.” Every line should carry necessary meaning.

Core relationships

Four questions, four semantics

Association

Who communicates with this use case? A solid line connects an external actor to a use case.

«include»

What required reusable behavior is inserted? The base use case depends on the included behavior to complete.

«extend»

What optional or conditional behavior may be inserted? The base use case remains meaningful without the extension.

Generalization

What specialized actor or use case inherits from a more general one? The child can refine inherited behavior.

Include versus extend

Required reuse is not optional variation

Decision«include»«extend»
BehaviorRequired for the base use case.Optional or conditional addition.
Base completenessThe including use case needs the included behavior.The extended use case is meaningful by itself.
Arrow points toThe included use case.The extended/base use case.

Fast diagnostic

Ask before drawing the arrow

  • If this behavior does not happen, can the base use case still achieve its goal? If no, consider «include».
  • Does the added behavior occur only under a condition or user choice? If yes, consider «extend».
  • Is one actor or goal genuinely a specialized kind of another? If yes, consider generalization.
  • Would plain text be clearer than another dependency? If yes, leave the line out.
Think like a software engineer

Should every use case «include» Login?

Usually no. Authentication can be a precondition or shared policy. Repeating «include» everywhere often adds clutter without improving understanding.

Key takeaway

«include» expresses required reused behavior; «extend» expresses optional or conditional behavior; generalization expresses specialization; association connects actors to goals.
