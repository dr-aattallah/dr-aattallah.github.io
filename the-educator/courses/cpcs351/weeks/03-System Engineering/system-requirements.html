System Requirements

System requirements define capabilities and constraints for the complete system before deciding which subsystem will implement each part.

3of 8 pages
Core lecture content Clarification & study aids
Learning focus

Differentiate among the phases of software development and understand software engineering within broader system engineering.

Core lecture

What you need to understand

  • Business goals and current situation are studied to identify needs.
  • Only a subset of needs may be selected because of budget and schedule constraints.
  • System requirements describe required capabilities, performance, quality, interfaces, and constraints.
  • Information collection uses presentations, observation/current operation study, surveys, interviews, and literature.

Worked example

ABHS requirement

“Serve 20,000 passengers per day” is a system-level capability; later it must be allocated across check-in, conveyors, scanners, staffing, and software.

Remember

System requirements say what the complete system must achieve before allocation says where it will be achieved.
